# Инструментарий движка RTS

Цель: чтобы «сделать игру на движке» означало — собрать контент (JSON),
прогнать проверки на компьютере, собрать APK. Без Android Studio и без телефона.

## Что уже есть

| # | Инструмент | Где | Что даёт |
|---|-----------|-----|----------|
| 1 | **Контент в JSON** | `app/src/main/assets/mod/` | юниты, здания, фракции, сложности, тексты, параметры карты — игра = данные |
| 2 | **Валидатор мода** | `tools/mod_check.py` | проверяет ссылки (казармы→юниты, меню→здания), границы карты, дубликаты ключей, наличие спрайтов; не даёт собрать сломанный мод |
| 3 | **Симулятор баланса** | `tools/simtest/run.sh stats` | партии бот-против-ИИ на JVM: % побед по сложностям, средняя длительность — настройка баланса без телефона. Грузит настоящий JSON из `assets/mod` тем же парсером, что и устройство |
| 4 | **Десктоп-превью** | `tools/simtest/run.sh shot` | PNG-снимок состояния мира (карта, руда, здания, юниты) на любой секунде партии; пример: `docs/shot_preview.png` |
| 5 | **Генератор спрайтов** | `tools/gen_sprites.py` | рисованные PNG-спрайты (PIL), контрольный лист |
| 6 | **Сборка APK** | `tools/build_apk.sh` | kotlinc + dex + AXML + подпись, без Android SDK |
| 7 | **Проверки APK** | `tools/check_structure.py`, verify | структура dex, наследование, invokedynamic, JAR-подпись |

## Минимальный цикл «сделать игру» (работает уже сейчас)

```
1. Отредактировать assets/mod/*.json        (юниты/баланс/фракции/тексты)
2. python3 tools/mod_check.py               (проверка контента)
3. tools/simtest/run.sh stats 20            (баланс сложностей)
4. tools/simtest/run.sh shot 7 normal 240   (посмотреть карту/бой)
5. bash tools/build_apk.sh                  (готовый APK в dist/)
```

Проверено на текущем моде:

```
$ python3 tools/mod_check.py
Мод валиден: юнитов 4, зданий 5, сложностей 3, фракций 2; предупреждений: 0

$ tools/simtest/run.sh stats 6
Баланс: 6 партий на сложность (бот игрока против ИИ движка)
  easy:   побед 1, поражений 5, не доиграно 0, средняя длительность 314с
  normal: побед 2, поражений 1, не доиграно 3, средняя длительность 219с
  hard:   побед 2, поражений 3, не доиграно 1, средняя длительность 272с
```

Пример вывода stats — первый баланс-инсайт: даже easy выигрывает у бота
уровня «здравый игрок» в 5 партиях из 6 — сложность easy стоит смягчить
(меньше стартовая волна `wave0`, ниже `income` или `miners`).

Инструменты simtest требуют те же зависимости, что и сборка APK:
python3+pip (`jdk4py`, `pillow`) и npm (kotlin-compiler) — run.sh сам
скачает компилятор при первом запуске.

## Дорожная карта (по приоритету)

| # | Инструмент | Зачем | Оценка труда |
|---|-----------|-------|--------------|
| 8 | **Карты-изображения**: `map.png` в моде (1 пиксель = 1 тайл, цвет = террейн) | автор рисует карту в любом графическом редакторе; движок грузит её вместо процедурной генерации | мало (движок + валидатор) |
| 9 | **Тинтовка спрайтов под фракции** (`gen_sprites.py --faction`) | сейчас red/blue захардкожены в генераторе; мод со своими цветами получит свой набор спрайтов автоматически | мало/средне |
| 10 | **Звуки мода** (`assets/mod/sfx/*.ogg` + SoundPool) | свои эффекты вместо системных сигналов | средне |
| 11 | **Сценарии/кампания**: условия победы, стартовые ресурсы, волны по времени — в JSON | не только «сразить базу», но и «продержаться 10 минут», «защитить конвой» | средне |
| 12 | **Конструктор юнитов**: веб-страница-форма → units.json (запускается локально) | делать баланс мышкой, не текстом | средне |
| 13 | **Скриптинг ИИ**: состав волн, приоритеты целей, темп атак — в JSON | разные характеры противников | средне |
| 14 | **Редактор карт с GUI** (десктоп): кисти террейна, расстановка стартов и руды | удобнее, чем PNG, для больших команд | много |
| 15 | **CI-релизы** (GitHub Actions): пуш → автосборка APK → ссылка на скачивание | не требовать локальной сборки вообще | мало (но нужен раннер) |

## Принципы движка (чтобы инструменты не разошлись с кодом)

- Контент — только данные (JSON); код движка не знает конкретных юнитов.
- Отсутствующая секция мода = встроенный fallback, но валидатор обязан предупреждать.
- Каждая проверка движка (структура dex, мод, баланс) вызывается из `build_apk.sh`,
  чтобы сломанная игра не собиралась.
- Ядро (`engine/`) не зависит от Android — все инструменты гоняются на JVM/Python.
